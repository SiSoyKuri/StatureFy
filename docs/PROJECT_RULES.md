\# Project Rules



\## Rule 1



Never implement a system before comparing multiple architectural approaches.



\---



\## Rule 2



Do not assume the previous implementation is correct.



The previous mod exists only as a reference.



\---



\## Rule 3



Favor compatibility over visual perfection.



\---



\## Rule 4



Avoid breaking compatibility with animation mods.



\---



\## Rule 5



Avoid breaking compatibility with resource packs.



\---



\## Rule 6



Avoid replacing vanilla systems unless absolutely necessary.



\---



\## Rule 7



Implement features in small incremental milestones.



\---



\## Rule 8



Every new rendering modification should explain:



\- Why it exists.

\- Why it is necessary.

\- Which compatibility problems it solves.

\- Which compatibility risks it introduces.



\---



\## Rule 9



When multiple implementations are possible, compare them before coding.



\---



\## Rule 10



The first solution is rarely the final solution.



Favor long-term maintainability over quick implementation.
